# Handyman

Handyman connects clients with skilled workers. A store seller refers a client, the client posts a problem (a broken dishwasher, a tripping breaker), matching workers send bids with arrival time, diagnostic fee and hourly rate, the client hires one, and both sides must rate each other before they can continue.

## Stack

| Part | Technology |
| --- | --- |
| Backend | ASP.NET Core on .NET 10, minimal APIs, vertical slices, in-house CQRS (no MediatR) |
| Database, auth, storage | Supabase: Postgres (schema `app`, EF Core migrations), phone sign-in, Storage |
| App | Expo (React Native + TypeScript, Expo Router) for iOS, Android and web |
| Tests | xUnit + Testcontainers on the backend; Jest + React Native Testing Library on the frontend |
| Hosting | Supabase (EU region) + one VPS with the API and the web build behind Caddy |

## Quick start

```bash
npx supabase start
./scripts/dev-env.sh                       # Windows: ./scripts/dev-env.ps1
dotnet run --project backend/src/Handyman.Api
cd frontend && npm ci && npm run web
```

Sign in with any seeded phone number from `docs/local-credentials.md` and code `123456`. Full details, phone setup and troubleshooting are in [runlocal.md](runlocal.md).

## Working with the AI team

Plan with `/plan <slice>`, approve stories, build with `/deliver <US-id>`, re-test with `/qa <US-id>`. Agents: product-owner, backend-dev, frontend-dev, qa-api, qa-app. Details in [workflow.md](workflow.md) section 9.

## Branches

`main` holds released code, `develop` is the integration branch. Each story gets a `feat/us-NNNN-slug` branch from `develop` and returns through a PR. Releases are PRs from `develop` to `main`, tagged `vX.Y.Z`. Details in [workflow.md](workflow.md) section 6.

## Working rules

- Every slice ships with backend and frontend tests; CI must be green before merge.
- Business rules live in the API. The app never reads or writes business tables through Supabase directly.
- Screens use only `src/ui` components and `theme.ts` tokens, so the coming mockups change the kit, not every screen.
- Update `workflow.md` in the same PR when a decision changes.
