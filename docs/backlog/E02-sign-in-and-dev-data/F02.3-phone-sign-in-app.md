## Description
A user opens the app (web, iOS or Android), enters a phone number, receives an SMS code (locally: the test code `123456`), enters it and is signed in. The session survives app restarts and page reloads, screens behind sign-in are guarded, and every API call carries the access token. A blocked user sees a clear message instead of a broken app.

## Stories
- US-0007 Request a sign-in code by phone
- US-0008 Sign in with the SMS code
- US-0009 Stay signed in and sign out
- US-0010 App calls the API as the signed-in user

## Business rules
- The app uses Supabase only for sign-in; it never reads or writes business tables through Supabase (workflow.md section 2, Business rules).
- SMS code limits are set in Supabase Auth's rate-limit settings, not in the app (workflow.md section 2, Business rules).
- Platform session storage lives in `src/lib/*.native.ts` / `*.web.ts` (workflow.md section 1, Frontend; CLAUDE.md hard rules).
- All user-facing strings live in `src/i18n/en.ts`, sentence case (workflow.md section 8).
