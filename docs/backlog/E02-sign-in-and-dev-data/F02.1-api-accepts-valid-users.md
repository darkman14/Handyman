## Description
Every API call under `/api` requires a valid Supabase access token. The API identifies the caller from the token's `sub` and their `app.users` row, and turns away blocked users before any business logic runs. Public endpoints (`/health`, later reference data and `/r/{code}`) stay open.

## Stories
- US-0001 API rejects calls without a valid sign-in token
- US-0002 API identifies the caller and refuses blocked users

## Business rules
- Roles (client, worker, admin) live in `app.users`, not in the token (workflow.md section 1, Auth).
- Blocked users get `403` on every API call (workflow.md section 2, Business rules).
- The API has no auth endpoints; sign-in and token refresh belong to Supabase Auth (workflow.md section 4).
- Errors use RFC 7807 problem details with a stable `code` (workflow.md section 4).
