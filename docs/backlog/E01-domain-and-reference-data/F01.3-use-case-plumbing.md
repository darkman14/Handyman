## Description
Every use case from E01 onwards is a command or a query on the in-house CQRS code (workflow.md section 5, CQRS). Commands are all-or-nothing and send pushes only for changes that were really saved; queries can never write; every use case has exactly one handler; and every failure reaches the app as a problem-details response with a stable code and no internal details. Users never see this directly, but it is what keeps "the hire went through but the push said otherwise" or a leaked stack trace from ever happening.

## Stories
- US-0015 Commands save all or nothing and push only after saving
- US-0016 Every use case has one handler and reads never write
- US-0017 Failures come back as problem details without internals

## Business rules
- Own CQRS implementation, no MediatR, no dispatcher; endpoints inject the handler they call (workflow.md section 1, CQRS; section 5).
- Commands use `AppDbContext`, queries use `ReadDbContext` (CLAUDE.md hard rules).
- Pushes are queued with `PendingPushes` and flushed only after commit (workflow.md section 5, CQRS; `.claude/rules/backend.md`).
- Errors use RFC 7807 problem details with a stable `code` (workflow.md section 4).
